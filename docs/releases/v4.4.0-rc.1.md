## Purpose

Provide one reproducible adoption and review point containing the current
normative text, executable Quint models, assurance profiles, schemas, test
vectors, and validation tooling. The package version is `4.4.0-rc.1`; the
normative baseline version is `4.3.0`. A package freeze fixes composition and
does not promote candidate requirements.

## Verification and interpretation

Reproduce from the exact candidate tag or resolved release commit:

```bash
python3 -m pip install -r requirements-ci.txt
bash scripts/build.sh
PYTHONPATH=. python3 -m pytest -q tests
python3 scripts/check_links.py
python3 scripts/check_release.py --frozen
```

Run the pinned Quint commands in [formal/README.md](../../formal/README.md).
CI uses Quint 0.33.0, Java 21, 5,000 sampled traces per model and bounded
symbolic verification at depth 12. Every checked property is conditional on
the state machine, abstraction, transition relation and bound. Finite tests
and bounded verification do not establish an unbounded proof.

The publication workflow checks all three CI workflows at the exact release
commit and attaches the manifest and formal map to a GitHub prerelease. The
run URLs and logs provide execution evidence; this document does not predeclare
successful results. The tag is never retargeted and release assets are never
overwritten by the workflow. A missing, failed or cancelled check prevents
publication.

On later development commits, `check_release.py` checks manifest structure and
the continuing compatibility of the declared normative owners. Use `--frozen`
on the release checkout to require exact file coverage and byte identity. To
prepare a new candidate, explicitly create its new manifest/version rather than
refresh an already published candidate.

## Candidate review and finalization

Before final v4.4.0:

1. Review composition, source precedence, partial formal mappings and gaps.
2. Resolve release-blocking contradictions in requirements, gates, evidence,
   schemas and test expectations, recording the disposition of each finding.
3. Check migration against the previous vector shapes and historical claims.
4. Record the review scope, reviewer identity and independence limitations.
5. Freeze a new final-version manifest and rerun CI on its exact commit.

Normative promotion of a candidate profile additionally follows that profile's
published promotion criteria and repository governance. Packaging does not
satisfy independent review, repeated heterogeneous reproduction, runtime
integration, or certification criteria. Finalizing a package need not promote
its informative profiles.

Compatible editorial or additive package work can proceed in the 4.x series.
Changing existing mandatory conformance obligations in a way that requires
implementation changes calls for an explicit major-version assessment. Keep
requirement IDs stable and publish the exact migration impact in either case.
